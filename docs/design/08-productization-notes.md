# FirmHound 产品化演进说明

> 依据：结合当前仓库真实实现状态，说明从 CLI 原型走向产品时需要补齐什么。原则是把“平台化叙事”收束为“可运行 CLI + 固件安全垂直能力 + 后续平台化路线”，避免对外承诺超出当前实现。

## 1. 总体判断

方向是成立的：IoT 固件安全、供应链合规、自动化漏洞挖掘都有现实价值。但从当前实现看，应避免把 FirmHound 描述成已经成熟的 SaaS 平台或全场景通用安全智能体。

更准确的表述是：

FirmHound 当前已形成可运行的固件漏洞挖掘 CLI 智能体原型，具备解包、攻击面建模、二进制审计、风险评分、反证验证和报告生成能力；后续可进一步封装为企业级 SaaS、在线评测平台或供应链固件安全服务。

## 2. 建议强化的部分

### 2.1 产品边界要更清楚

建议把产品分成三层：

1. 当前已完成：CLI 固件漏洞挖掘智能体。
2. 短期提交版：CLI + 报告模板 + 一键部署/演示材料。
3. 长期商业版：Web/SaaS 平台 + 固件资产库 + 持续监测 + 合规报告。

图表建议：

- “产品演进路线图”：CLI 原型 -> 实验室版 -> 企业平台版。

### 2.2 对外材料中的数据要分级

建议区分：

- 已验证数据：来自当前项目测试和真实固件回归。
- 参考数据：来自公开报告、行业资料或第三方研究。
- 规划数据：商业预测、未来性能指标。

不要把规划数据写成已实现数据。

### 2.3 技术门槛要落到具体实现

可以强调：

- 阶段机编排。
- Skill 知识包。
- JSON Schema 证据契约。
- 十维评分。
- 反证优先。
- 外部工具双轨融合。
- 加密固件识别和安全降级。

这些比“用了大模型”更能说明系统做了什么。

### 2.4 商业价值要贴合固件安全

建议重点客户：

- IoT 设备厂商。
- 路由器/网关/摄像头厂商。
- 工业互联网设备厂商。
- 安全实验室。
- 测评机构。
- 供应链安全审计团队。

典型付费场景：

- 固件上线前安全检测。
- 固件版本差异和漏洞复发检测。
- SBOM/漏洞证据报告。
- 合规材料辅助。
- 红蓝队训练样本分析。

## 3. 需要谨慎修改的表述

### 3.1 关于“通用网络安全智能体”

当前产品更准确是：

- “通用网络安全智能体框架下的固件漏洞挖掘垂直 Agent”
- “面向 IoT 固件安全的自主决策 CLI 智能体”

不建议直接写：

- “覆盖渗透测试、应急响应、云安全、代码审计、固件逆向的全场景通用智能体”

除非后续真的补齐对应模块。

### 3.2 关于“0-day”

可以写：

- “支持未知漏洞候选发现”
- “面向零先验固件样本生成高风险候选”
- “为 0-day 挖掘提供自动化线索和证据链”

不要写：

- “已自动确认多个 0-day”

除非有动态复现、厂商确认或 CVE 编号。

### 3.3 关于“加密固件解密”

可以写：

- “能够识别加密载荷并保存解密所需切片”
- “支持在提供密钥/密码/升级工具逻辑后继续解包”

不要写：

- “自动解密所有加密固件”

## 4. 建议新增章节

### 4.1 产品实测数据

加入：

- 10 个 Schema。
- 10 个 Skill 包。
- 4 个外部分析器。
- 9 个 CVE fixture。
- 332 个 pytest 收集项。
- 336 passed，1 skipped。
- 3 个真实固件案例。

### 4.2 安全合规设计

加入：

- 授权必填。
- 路径白名单。
- 命令黑名单。
- 私有 IP。
- PoC 脱敏。
- 报告合规。

产品定位是防御侧分析工具，这些约束是定位的一部分。

### 4.3 交付版收敛路线

发布前建议按下面顺序收敛：

1. 交付包整理（代码、依赖锁、许可证）。
2. 用户手册与测试报告定稿。
3. 汇报材料与演示脚本录制。
4. AC15 真实案例演示。
5. BE3LPro 加密固件边界演示。

## 5. 对外汇报建议

汇报结构可以参考：

背景 -> 痛点 -> 方案 -> 架构 -> 技术创新 -> 实验数据 -> 价值 -> 规划。

但建议换成 FirmHound 真实表达：

- 不讲“修复平台”，讲“固件漏洞挖掘 CLI 智能体”。
- 不讲“前端可视化平台”，讲“可复现 CLI + 结构化报告”。
- 不讲“百级真实 CVE 实测”，讲“9 个 CVE fixture + 3 个真实固件样本 + 待补真实外部工具闭环”。

## 6. 最推荐的一句话定位

FirmHound 是面向智能联网设备固件的漏洞挖掘 CLI。阶段机编排解包、攻击面恢复、二进制审计、风险评分、反证验证和报告生成，把依赖专家经验的固件分析流程做成可复现、可审计的自动化工作流。
